## 二、A：折行拆行（第一个修的）

### 根因

论文在窄首列里把长名字**印成两行**，数值在第一行：

```
2-甲基        280.73  295.28  347.00  ...
丁醇
```

网格一行一个基线，于是 `2-甲基` 成了一个化合物，`丁醇` 成了一个只有一格的行——而
`extract_band.py` 里有一句「至少两格」的过滤把它**整个丢掉**。名字被静默截断，
**没有任何东西会报警**。

### 修法

在丢行**之前**把续行并回上一行，并列出全部合并记录（`out/re整理/wrap_report.txt`，
含被拒的）。判据是「形状无可置疑」：只有首列一格、长度 ≤8、上一行有真实测量值、
上一行名字未以完整官能团结尾、两边都不是说明性文字。

两条是踩坑后加的：

- **上一行必须以未完成的名字结尾**。否则三行折行的第一片会挂到上一个化合物头上：
  `糠醛` + `3-羟基` → `糠醛3-羟基`。中文白酒名后缀明确（酯/醇/醛/酸…），折行总切在
  后缀**之前**，所以「上一行已以完整后缀结尾」就是「新开一行」的确证。
- **硫曾漏在后缀表外**，`二甲基三硫` + `脂肪酸` → `二甲基三硫脂肪酸`，编出物质。

### 效果

全库 48 处、23 个不同名字，逐条核对无误：

```
2-甲基   + 丁醇     -> 2-甲基丁醇          亚油酸乙 + 酯  -> 亚油酸乙酯
2,5-二甲 + 基吡嗪   -> 2,5-二甲基吡嗪      棕榈酸乙 + 酯 -> 棕榈酸乙酯
三甲基吡 + 嗪        -> 三甲基吡嗪          油酸乙   + 酯 -> 油酸乙酯
四甲基吡 + 嗪        -> 四甲基吡嗪
```

## 五、CAS 双库交叉

### 为什么必须

之前 CAS 全部由 PubChem 单独决定——**单点故障**。而 `fill_cas` 的往返校验查不出来，
因为它往返的是同一个库。

### 选库

试了三个：CAS Common Chemistry 需 API key（401）、ChEBI 接口已变（404）、
**NIST Chemistry WebBook 可用**。选 NIST 因为它是人工编纂的非商业汇编，覆盖面比
PubChem 窄——**它认识的名字就是化学家审过的名字**。

### 判定

| 情况 | 处理 | 格数 |
|---|---|---|
| 两库一致 | 写入，标 `反查·双库一致` | 351 |
| PubChem 空，NIST 有 | 写入，标 `反查·NIST` | 9 |
| PubChem 有，NIST 空 | 写入，标 `反查·PubChem` | 2396 |
| **两库不一致** | **留空 + 列出两个值** | 7 |

最后一条刻意：证据不支持在两个库之间偏袒某一个，挑一个等于在优先级 1 的列里写一个
自信的数字，换的只是一枚硬币。7 格是 `Ethyl L(--)-lactate`、`Ethyl 4-decenoate`、
`Ethyl 2-decenoate`、`2-Nonen-4-one`，都属异构体/定位编号分歧，需人工判断。

### 途中发现并修掉的严重问题

第一轮跑出来，中文名**普遍返回同一个 CAS**（`7440-42-8`）。查证后发现：拿中文名查
NIST，它不报「查不到」，而是**返回一个完全无关的记录**——`1-辛醇b` 返回的是**硼（Boron）**
的页面，我把它的 CAS 当成了答案。

一个会编造答案的第二数据源，比没有第二数据源更糟。现在：

- **非 ASCII 名字直接拒绝**（NIST 本就只索引英文名）；
- **拒绝结果列表页**（`Search Results` / `Name Not Found`）；
- 加了**启动自检**：查一个必须认识的名字、查一个必须拒绝的名字，不符合就中止；
- 清掉 458 条被污染的缓存后重跑。

现在的行为是对的：`(2,2-Diethoxyethyl) benzene` 两库都返回 `6314-97-2`，
**正是论文在这一行印刷的 CAS**——之前是反查和原文互相矛盾。

## 九、列N（丢失的列标题）回捞

问的是「剩下的 列N 能不能再提取」，答案是**大部分能**，而且病根不在提取阶段，在表头切分。

### 先量清楚有多少

按真正走的代码路径（`classify_columns` → `promote_header_rows`）统计，不是按 band 文件里
存着的 `header_rows`——后者会把表体散文当成表头，量出来是错的 33 张表；真实数字是 **18 张表、
30 列**。另外逐列查了填充率：**没有一列是空的**（全是空列），30 列都有数据，所以不是该剔除
的废列，是真丢了名字。

### 病根一：正文散文被当成表头（band_12 等）

有些页面，表格上方的整段正文被 `extract_band` 交给了 `header_rows`。于是那十几行散文占满了
表头块，**真正的表头行被推进了表体**，它下面的每一列就此失去名字。

修法是表头块里出现「句子」的整行直接剔除（单元格超过 24 字就是句子，不是标签）。

### 病根二：表头行本身没有单位（band_19 等）

原来只有「含单位 + 大半是标签」才算表头。但论文常常把单位单独印在更上面一行，标签行是光秃的
的——表1 就是 `X0 X1 X3 X5 X8` 当表头、`mg/L` 另起一行。判据改为：**一行短标签、且它下面一行
是数字**，也算表头。

这条判据第一次写松了，把 `乙醚` 那种「未检出」的全横杠行也当成表头提升，浓度列表头变成了
`-`。补了一个条件：整行填充格中标签要占到一半以上。横杠行是 2/8，标签行是 5/5。

### 病根三：读表头时读的是旧的那份

`sample_label()` 直接读 `t["header_rows"]`，而提升后的表头只存在于 `classify_columns` 的返回值
里、**没有写回表对象**。所以表头被正确提升了、列名却仍然显示 `列N`。改成传入提升后的行。

以上三条修完：**18 张表 → 12 张表**，完全恢复的有 6 张，拿到的是论文上印的真名字：

```
表1    X0   X1   X3   X5   X8            （年份样品）
某表   优级 丢糟                        （等级）
表     JZG-1 JZ12-1 CZ5-1 JZB-1 …        （样品代号）
某表   均衡组 微涩组 较涩组 涩味组 苦味组   （味觉分组）
某表   S-Y5-H S-Y4-H A-G1-H J-Y1-H …     （样品代号）
```

### 病根四：网格把表头整体错位（剩下的 26 列）

剩下 9 张表（26 列）我回到原页核对了，**论文那一格本来就是空的**：

- band_28 印的是 `含量 | 相对保留时间 | (空) | 含量 | …`，网格把那个空当成了独立的一列；
- band_26 附表7 的表头行**整体右移了一列**（`化合物|阈值|__|GRD-1|GRD-JC|…`，数据是
  `乙酸乙酯|32551.6[66]|42|46|…`），所以 `col2` 的真名是 GRD-1，但那一列已经在 col3 有了。

这种情况没有可读的文字可捞，硬补等于**造一个论文没印的列**，所以留 `列N`。

### 中间还修了自己写出来的一个 bug

`hdr_rows = list(t["header_rows"])` 是**拷贝**，往拷贝上 append，报告里写着「取到 定量离子」、
文件里一个字节没变。这是最难查的一类——报告和磁盘不一致，而报告是「成功」的。

## 十、OAV 被当成浓度（这一轮最严重的一个）

审计「列N」时顺手发现同一张表里两个 `GJ-1573` 值不同。渲染原页核对：

| | LZ-2016 base SAB | GJ-1573 |
|---|---|---|
| 浓度 (μg/L) | 7 606 936 | 1 487 026 |
| OAV | 137 558 | 26 890 |

7 606 936 ÷ 55.3 = 137 538 ✓ —— 所以 137 558 和 26 890 都是 **OAV**。工作簿此前把 `26 890`
写成了「浓度 GJ-1573」，**清洗表里也照抄了这个错**。同样地，另两张表（band_12、band_13）
的 OAV 组标题也都被当成浓度列。

### 根因：合并表头只在「组标题印在组首」时才对

论文把 `OAV` 这种组标题**居中**印在组上方，网格把它记在组中央那一列。向右补空格的做法于是
把组切成了两半。正确做法是从子表头行反推跨度：**组标题覆盖它左右相邻标题之间、且下面各自
带标签的那一整段列**；而 `阈值` 下面只有 `(mg·L-1)` 这种单位，是叶子节点，只管自己一列。

三张表都渲染原图逐张核对，改完与原图完全一致：

```
en_01   thr=[2]            oav=[5,6]        data=[3,4]
band_13 thr=[2]            oav=[3..10]      data=[]
band_12 thr=[2]            oav=[3..6]       data=[]
```

这条改动让工作簿少了 88 行——那些是被错标成浓度的 OAV，本来就不该在里面。

### 附带修掉的表头丢失

同一轮里，band 路线剩下的无名列全部归零：

- band_26 t17/t21/t22（附表7、附表8）：表头在网格里整体错位或根本没进来，**按原页文字层
  逐列核对后写死**在 `recover_headers.KNOWN_HEADERS`，每条都注明出处页码。
- band_21 t6/t8（表2-3 浓度梯度）：真表头 `风味物质|1|2|3|4|5` 在 p36，续表在 p39。
- band_24 t1：`2 年陈 / 3 年陈 / 5 年陈` 之前因为「2 年陈」以数字开头被误判成数值而没能提升。

关键的一处：判断「这是数值还是标签」原来用**前缀匹配**，`2 年陈`、`1 2` 都被读成数字。
改成整格匹配，并规定**空格只有在后面恰好跟三位数字时才算千分位**——`4 782.47` 是一个数，
`1 2` 是网格把梯度列 1、2 并进了一格。

## 十三、OCR（bitmap）路线：按字框重建

### 两个病根，都不在「提取」上

**并格。** T09（附表8，酯类）是 6 列宽的表，网格只建了 5 列。查字框：
`19.62±1.73a` 在 x 1199–1415，`18.06±2.69a` 在 x 1476–1690——**本来就是两个独立的框**，
相距 61px，被写进了同一格。一格里两个标准差的数不是数，清洗表也没地方放。

**表头在上一页。** 跨页续表的首行不在这个裁剪里，于是网格无从给列命名，只能给 `列N`。

### 重建

按 x 聚类分列，每个框各归其列——并格自然消失。行不靠 y 阈值分：香气描述单元格换行成
`MS,RIL,` / `Aroma` 两行，行内跨度 53px 而行距 107px，**「格内」和「行间」的边界只差 2px**，
任何阈值都会把一行拆成三行或把三行并成一行（第一次试就是 25 行变 77 行）。改用**最左列
做行锚点**，其余框按最近锚点归行。

### 表头：从同一篇论文的另一个裁剪里按列位置找

跨页表的表头在上一页，但**列还在，x 位置不变**。附表的列名 `物质名称 / 一级好酒 / 一级差酒 /
二级好酒 / 二级差酒 / 三级酒` 在一个裁剪里，续表裁剪的测量值正好落在同样的 x 上。这个对齐
就是识别依据——**没有文字层也拿得到**。

四条拒绝规则，每条都是先配错了才加的（**错表头比没有表头更糟**）：

| 拒绝 | 原因 |
|---|---|
| 只认同一页 ±1 的裁剪 | 同篇论文隔几页就有同版式的另一张表，取到过 `RI/物质名称/香气描述/鉴定方式` 去命名一张列是 `一级好酒/一级差酒` 的表 |
| 拒绝出现在本表数据里的词 | 数据行被当成表头，`1-Butanol`、`乙酸乙酯` 成了列名 |
| 拒绝化合物名 | 无论文本多像标签，以物质命名的列就是数据行 |
| 补列名只在命中裁剪内部找 | 跨裁剪去找，取到了别的表的数据行，`醇类` 成了列名 |

### 闸门：只接受能证明无损的重建

按 x 重建**会出错**，两次实测都差点污染数据：T08 的行锚点错了，7 行变 5 行；T22 凭空多出
每行 4 格。所以重建必须过两道检查，否则原样保留并记进 `bitmap_rebuild.txt`：

1. 行数不得变少，且原表每行的首格都得在重建结果里还在；
2. 每行填充格的增量，不得超过原行里并格能解释的量（并格含 k 个测量值 → 最多多出 k−1 格）。

第一版的并格计数只在「含一个 ±」时才生效，于是 `3337.10 1875.00`、`1 1`、`256 256`
全被算成 0，把好表也拦了。改成按空白切分数测量值个数，并且**不含测量值的格子一律不算并格**
——CAS（`108-64-5`）、溶剂说明（`46% ethanol/ water solution`）都不该给重建发一张「可以
凭空造列」的许可证。
